| 2026-11-20 | root | `protocol: openai` means the Chat Completions API. | Works with any OpenAI-compatible `base_url`. Chosen with Cal. |
| 2026-11-20 | root | The builtin composer is the hidden subcommand `gllmh composer`, a child process. | The valet then treats builtin and custom composers the same way. |
| 2026-11-20 | S0 | `send` gains `local: bool`, true when a UI or controller submitted on local.sock. | Section 3 resets `hops` to 0 for UI/controller submits, but the broker cannot otherwise tell them from service or turn sends. `root` still follows `caused_by`. |
| 2026-11-20 | S0 | `init` gains `edges` (hello's edges). | The builtin composer's header names whom the agent may message and direct (section 7), and init carried no edges. |
| 2026-11-20 | S0 | `content_block` gains `is_error` on `tool_result`. | Both providers flag failed tool results; a failed, denied or refused call should reach the model as an error. |
| 2026-11-20 | S0 | Error codes `bad_frame`, `unknown_op`, `bad_input`, `internal` on every line; `no_hello` on the broker line; `broker_unavailable`, `bad_kind` on submit. | The spec lists only op-specific codes; these cover malformed traffic. |
| 2026-11-20 | S0 | `notify` is a request whose reply the valet ignores. | Section 6 frames are request/reply; a fire-and-forget op would be a fourth frame kind. |
| 2026-11-20 | root | MCP over a unix socket is newline-delimited JSON-RPC, the stdio framing. | The spec names "a socket" without a transport. |
| 2026-11-20 | M3.3 | Attach treats message text and directive block contents as strings. Directive arguments use shell-style quoting, and attach leaves `caused_by` unset. | The terminal syntax provides no causal parent or identity. The valet and broker remain responsible for identity, routing and causal metadata. |
| 2026-11-20 | M2.1 | A result must come from the directive's recipient as a user and be addressed to the director's user, including the owner of a service director. The first accepted result settles the obligation in every delivery state. | Section 6.1 leaves the destination check implicit. Section 2 requires one result to reach the director, and section 4 keeps accepted rows immutable when retried or expired. The log checks the obligation and inserts the result in one transaction. |
| 2026-11-20 | M2.1 | Reject a fresh send with an unknown `caused_by`. Deliver and list a run in log append order, keeping a requeued row in its original position. | The log cannot assign the specified root without a parent. Append order remains stable when acceptance times tie or the clock moves backward, and requeue changes only state. |
| 2026-11-20 | A1 | Retry explicit retryable submit errors. Treat loss of a submit reply as ambiguous: a dispatcher or one-shot timer exits with an error, and a recurring timer reconnects for the next tick. | Section 6.3 has no submit idempotency key or lookup for an unknown interaction ID. Replaying an ambiguous submit can create a second interaction. |
| 2026-11-20 | A1 | Recurring timers skip missed intervals and omit `caused_by`. A dispatcher's `result_file` holds one JSON line for the matched result and is replaced on success. | Skipping missed intervals avoids a burst after an outage. Section 2 gives each recurring send a fresh run. The file mirrors the single stdout result. |
| 2026-11-20 | A1 | The acceptance test builds the two examples once with Cargo and reads their executable paths from Cargo's JSON build output. | The tests exercise the actual child processes and work with Cargo target-directory overrides without adding dependencies. |
| 2026-11-20 | M3.1 | Start a turn with zero steps and increment before each model call, beginning at step 1. The valet supplies the configured limit to the increment. | Counts model calls and refuses to exceed the section-4 bound even on a resumed turn. |
| 2026-11-20 | M3.1 | A broker delivery commits its receive directly as succeeded. Its turn field is the trigger when the delivery opens a turn and absent otherwise. Use local insertion order for the turn queue. | The transaction is the complete receive operation, and redelivery must leave its first record and turn intact. FIFO survives a clock change. |
| 2026-11-20 | M3.1 | Broker lookup can settle a requested or running send as succeeded. The normal success path requires running. | Section 5 requires settling every unfinished send known to the broker without executing it again. |
| 2026-11-20 | M3.1 | Running-turn recovery reports already interrupted tool actions as well as unfinished tool actions. | A second crash between recovery steps 4 and 5 must retain the tool-call evidence so the valet interrupts the turn instead of resuming it. |
| 2026-11-20 | T1 | Fake LLM rules are one-shot unless `repeat: true`. Record requests and select rules together before applying an optional delay. | Scripts can express successive steps, and concurrent requests cannot consume the same rule or reorder the log by finishing early. |
| 2026-11-20 | T1 | Substring matching reads the latest user or tool message, joining its text blocks with newlines and reading nested Anthropic tool-result text. | Both provider encodings can match tool output without accidentally matching earlier turns or metadata. |
| 2026-11-20 | M1.1 | Require config directories used by the runtime to be `0750` and its profile files to be `0640`, all `root:gllmh`. | Section 5 lists `0640` under `/etc/gllmh/`. Directories need search permission to let the broker reach the files. |
| 2026-11-20 | M1.1 | Absent edge maps grant no permissions. An omitted builtin mode uses message mode. | The section-7 service rule defaults to no edges. The builtin block is optional, so the default uses the conversation timeline and preserves its single-turn limit. |
| 2026-11-20 | M1.1 | Require profile names to match the requested file stem and runtime membership to list each user once. In production reject distinct system account names that resolve to the same UID. | Socket identity must map to exactly one participant under section 4. Dev mode checks duplicate literal account names without OS lookups. |
| 2026-11-20 | M1.1 | Resolve and validate profiles reachable from the selected runtime. Expand `"*"` to all tool profiles in filename order, or an empty list if the tool directory is absent. Keep configured paths in the resolved profile. | A config tree can contain independent workflows. Stable tool ordering makes hello deterministic, and the recipient can resolve paths against the appropriate system user's home when needed. |
| 2026-11-20 | M4.1 | `content_block.raw_json` optionally carries the exact JSON spelling of a thinking block alongside the parsed `raw`. Only blocks for the chosen protocol are replayed. | JSON-lines frames and stored JSON values can escape line breaks in a string, while parsing `raw` alone loses whitespace, key order and escape spelling. Custom composers that only supply `raw` remain compatible. Switching protocols leaves text and tool history usable. |
| 2026-11-20 | M4.1 | Anthropic manual thinking uses half of `max_output` rounded down, with a minimum budget of 1,024. An enabled request needs `max_output > 1024`. | The provider requires a minimum budget below its output cap. Reserving the rest leaves space for the answer. |
| 2026-11-20 | M4.1 | Chat Completions uses `max_completion_tokens`; when thinking is on, it sends `reasoning_effort: medium`. Returned `reasoning_content` can be replayed when the composer supplies it. | The cap includes reasoning and visible output. Medium is a supported effort for reasoning models, and compatible endpoints may require their reasoning field during tool use. |
| 2026-11-20 | M4.1 | OpenAI tool results with `is_error` use a `[tool error]` line before the tool output. Anthropic uses its native flag. | Chat Completions has no tool-result error flag. Keeping the marker inside tool content preserves both the failure signal and the call ID. |
| 2026-11-20 | M4.1 | Retry the recorded request bytes within one `llm_call`. Use jittered exponential backoff starting from 250 ms and capped at 30 s before jitter, with integer `Retry-After` seconds as a minimum delay. Disable redirects and transport-level retries. | The valet can record the exact model input before the first attempt, and the call retains control of the endpoint and attempt limit. |
| 2026-11-20 | M4.1 | An omitted `api_key_file` allows an unauthenticated endpoint. A configured key file must be readable and contain a usable key. | Local compatible endpoints may omit authentication. A misconfigured credential fails before any provider request. |
| 2026-11-20 | M4.1 | Usage counts Anthropic's cache reads and writes as input tokens. Usage may be absent for compatible Chat Completions endpoints. | The normalized input count covers the full prompt, and absent provider measurements stay distinguishable from zero. |
| 2026-11-20 | M5.2 | Implement the small MCP JSON-RPC client directly, using reqwest with rustls and an SSE decoder for HTTP. | The rmcp Unix-socket HTTP transport speaks HTTP, while GLLMH sockets use JSON lines. Owning the small exchange also lets stdio, Unix and HTTP share the exact method-not-found and deadline handling. |
| 2026-11-20 | M5.2 | Apply a 120-second timeout to each MCP step. A missing tool description serializes as JSON null. | The standalone client has no tool-profile context. The valet can impose its outer run deadline, and list output keeps all three keys without inventing descriptions. |
| 2026-11-20 | M2.2 | Return `bad_input` when a fresh non-result send names an unknown `caused_by`. Count compact JSON bytes for the present body and context, including explicit JSON null, and reject fields assigned to a different interaction kind. | There is no broker code for an unknown parent or a mismatched payload. This preserves causal roots and applies the configured limit to the exact JSON values stored by the log. |
| 2026-11-20 | M2.2 | For `lookup`, search the user's own sender first, then its configured services in name order. | A valet normally generates each action ID once across all its senders. The order makes ambiguous references deterministic without disclosing another user's sends. |
| 2026-11-20 | M2.2 | For `close`, report a missing row as `not_yours` and a different outcome on an already closed row as `not_acked`. | The protocol has no missing-row or conflicting-outcome code. This preserves recipient-only access and keeps a recorded outcome immutable. |
| 2026-11-20 | M2.2 | Add serve options `--db` and `--expire-interval-s` (default 60). Dev sockets use the explicit run directory or `GLLMH_RUN_DIR`, then `$XDG_RUNTIME_DIR/gllmh/users` when set, then the shared default. | These overrides support isolated dev runs and tests. Expiry still uses the TTL in the runtime profile. |
| 2026-11-20 | M4.2 | In both modes, estimate one token per four Unicode characters of each serialized rendered message (including its role and content fields, excluding tools and outer reply framing). Drop the oldest unpinned group until it fits. A model call and its tool results are one group. Keep the system message and trigger even when they exceed the budget. | Preserves required context and tool pairing while applying the budget to the context the composer actually returns. |
| 2026-11-20 | M4.2 | Read tuning paths in order on each compose, expanding `~` against the process home. Log and skip unreadable or non-UTF-8 files. List message and directive recipients separately, gated by the corresponding configured tool and using only the agent's own edges. | Keeps compose available when tuning text is unavailable and reports the topology assigned to the agent by the broker. |
| 2026-11-20 | M4.2 | Keep consecutive same-role messages separate. Replay the stored thinking JSON values unchanged when requested. The existing typed wire and action output use JSON values, so original JSON whitespace and object key order are unavailable there. | Leaves provider normalization to the valet and carries the stored provider payload, including signed strings, through the existing contract. |
| 2026-11-20 | M4.2 | If a received result opens a directive-mode turn, render its trigger using the normal receive format. Pair tool results by parent action ID and call ID. A paired unfinished row reports its state and a missing row reports `not run`. | Section 2 lets a result open a turn. Per-turn scope keeps that result isolated, and reporting unfinished state avoids implying the tool completed. |
| 2026-11-20 | M4.2 | Missing turns and invalid initialization use the common `bad_input` code. On stdin EOF, finish accepted compose requests and flush their replies. | The framing contract permits the peer to close its input while replies are still pending. |
| 2026-11-20 | M1.2 | Omit `WorkingDirectory=` when a service has no `cwd`. | The service schema makes `cwd` optional. Omitting it preserves systemd's default and leaves the valet's separate directory rule intact. |
| 2026-11-20 | M1.2 | After profile validation, reject values that cannot be rendered safely as literal systemd unit names, directives or executable paths. | Build must preserve user and service names for socket identity and cgroup checks, and the rendered unit must preserve the configured user, executable and working directory. |
| 2026-11-20 | M3.2 | The valet exits non-zero when its broker connection closes; systemd restarts it and recovery runs. | One restart path instead of a second, reconnect-time recovery. The valet's units are `Restart=<restart>` and ordered after the broker. |
| 2026-11-20 | M3.2 | `gllmh valet --data-root <dir>` sets user_data_store to `<dir>/<user>`. | In dev mode every user runs as the caller and shares one home, so the profile's `~/.gllmh` would collide. |
| 2026-11-20 | M3.2 | A send refused by the valet's edge pre-check is recorded as a `failed` send, not `denied`. | Section 2 treats a refused send like a failed tool; `denied` is reserved for tools outside the agent's tool_profiles. |
| 2026-11-20 | M3.2 | A user with no composer re-sends `close` when a redelivery hits an already recorded receive. | A crash between ack and close would otherwise leave the interaction `acked` forever; close is idempotent. |
| 2026-11-20 | M4.3 | The valet asks for thinking only when the llm_profile's `thinking.native` is not `never`, whatever the compose reply says. | The builtin composer turns thinking on for every `react` turn; a model that cannot think would reject the call. |
| 2026-11-20 | M6.2 | `gllmh status` prints tab-separated columns and uses `-` for absent outcomes and close times. Socket connect failures and disconnects before the reply report the CLI-only code `connection_failed`. The valet's error codes pass through to stderr. | Section 6 leaves table formatting and local transport errors unspecified. This keeps fields distinct and reports failure without changing the local or broker protocol. |
| 2026-11-20 | M5.1 | Load executable schema envelopes at startup, requiring a nonempty `name`, a string `description`, and an `input` schema object. Expose the profile name and fail startup for unreadable or malformed envelopes. | A configured tool gets a stable callable name and schema for the valet's lifetime. Startup errors identify configuration problems before the agent starts turns. |
| 2026-11-20 | M5.1 | Record malformed send-tool arguments as a failed `tool_call` with a `bad_input` tool result. Send requests with well-formed arguments always use the valet's recorded send path, including recipients outside the edge enum. | A malformed request cannot be represented as a typed broker `SendInput`. The failed call preserves the original arguments and call identity, and the existing send path preserves write-ahead and reports edge refusals as `not_allowed`. |
| 2026-11-20 | M5.1 | For nonzero exits, prefix the tool result's stdout with the exit code. Encode signal exits as 128 plus the signal number and decode invalid UTF-8 with replacement characters. | Model-facing errors explain the failure while preserving textual output and satisfying the run contract's integer exit code and string streams. |
| 2026-11-20 | M6.1 | Checkpoint a directive's final text in the same transaction as the terminal turn state. Recover ended directives until the broker confirms close, including older ended rows with no text checkpoint. | Preserves the outcome and exact available text across a crash before send. The send's success row or broker lookup prevents a second result after a crash before close. Older rows have no checkpoint, so their recoverable result can omit the body if still owed. |
| 2026-11-20 | M6.1 | Retry explicit retryable result errors with five exponential delays from 250 ms to 4 s. Resolve ambiguous sends by client_ref before retrying. If the send still fails, log the failure and keep the directive unclosed for restart recovery. | Bounds the time spent retrying and preserves the obligation and result payload. Closing requires confirmed acceptance. |
| 2026-11-20 | A3 | Generate units in a Nix build with `gllmh build --dev`. Resolve home-relative paths against the final NixOS accounts before rendering, project the generated install directives into target dependencies, and enable the target under `multi-user.target`. | One renderer keeps the profiles and units in sync. The sandbox lacks final passwd entries, and NixOS installs package units without running `systemctl enable`. The broker checks accounts, permissions and socket ownership at startup. |
| 2026-11-20 | A3 | Use private homes under `/var/lib/gllmh-users` and create the configured store directories with tmpfiles. | The rendered valet unit needs its working directory before the valet can create its store. NixOS owns account and filesystem setup. |
| 2026-11-20 | A3 | Split the acceptance LLM profile into two copies with separate secret paths for `agent` and `worker_agent`. | The fixture shares the provider configuration, but one key file cannot meet the owner check for two distinct system users. |
| 2026-11-20 | A3 | Supply a one-shot timer message and a dispatcher directive in the acceptance NixOS instance. | The example executables require service config JSON. One submission per service start gives A4 a repeatable trigger for each workflow. |
| 2026-11-20 | M5.3 | Skip and log MCP names with an empty tool component, an invalid provider character, or an expanded name longer than 64 bytes. Also skip every MCP alias claimed by multiple selected tools or equal to a configured profile name. | Preserves unambiguous dispatch and hazardness attribution. Rewriting or truncating a server name could route a recorded call to a different tool. |
| 2026-11-20 | M5.3 | Use the tool profile's timeout and the effective tool cwd for discovery. Supply an empty provider description when the server omits it. | Discovery is bounded and resolves relative server locators just as a call does. The provider schema requires a string description. |
